# Отчёт по заданию A3: Шифрование отдельных строк и переменных

### 1. В чём разница между `ansible-vault encrypt` (файл) и `ansible-vault encrypt_string` (строка)?

| Характеристика | `encrypt` (файл) | `encrypt_string` (строка) |
|----------------|------------------|---------------------------|
| **Что шифрует** | Весь файл целиком | Отдельную строку/переменную |
| **Результат** | Зашифрованный файл | YAML-тег `!vault \|` с зашифрованным значением |
| **Использование** | `vars_files: secrets.yml` | Вставка прямо в YAML-файл |
| **Когда использовать** | Много секретов в одном месте | 1-2 секрета внутри плейбука/роли |

Пример `encrypt_string`:
```bash
ansible-vault encrypt_string "my_password" --name "db_pass"
Результат:
db_pass: !vault |
          $ANSIBLE_VAULT;1.2;AES256
          61626364...
2. Когда лучше шифровать весь файл, а когда — только строку?
Шифровать весь файл (encrypt), когда:

    Много секретов (10+ переменных)
    Секреты используются в нескольких плейбуках
    Нужно централизованное управление секретами
    Разные команды работают с разными файлами (dev vs prod)

Шифровать строку (encrypt_string), когда:

    1-2 секрета внутри роли или плейбука
    Нужно быстро зашифровать пароль без создания отдельного файла
    Секрет специфичен для одной задачи
    Прототипирование и быстрые тесты

Best practice: Для production использовать encrypt с отдельными файлами per environment.
3. Что означает !vault | в YAML?

    !vault — это YAML-тег, который говорит Ansible: "это значение зашифровано Vault, расшифруй его перед использованием"
    | (pipe) — YAML-индикатор literal block scalar, означает "сохранить переносы строк как есть"

Вместе !vault | означает: "многострочное зашифрованное значение, которое Ansible должен расшифровать".
Ansible распознаёт этот тег и автоматически вызывает Vault для расшифровки при загрузке переменных.
4. Как бы вы расшифровали строку вручную (без Ansible)?
Никак. Зашифрованная строка Vault не может быть расшифрована без Ansible и правильного пароля. Это не Base64 и не простое кодирование — это полноценное AES-256 шифрование.
Для просмотра содержимого нужно использовать Ansible:
# Просмотр зашифрованного файла
ansible-vault view secrets.yml --vault-password-file .vault_pass

# Редактирование
ansible-vault edit secrets.yml --vault-password-file .vault_pass

# Расшифровка в открытый файл (не рекомендуется для production!)
ansible-vault decrypt secrets.yml --vault-password-file .vault_pass
Важно: После decrypt файл остаётся в открытом виде — нужно снова зашифровать или удалить.
