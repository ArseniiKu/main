# Отчёт A1: Jinja2 + Handlers


Что такое Jinja2 и зачем он нужен в Ansible?
Jinja2 — шаблонизатор на Python. В Ansible он нужен для того, чтобы собирать конфиги «на лету»: один шаблон + переменные (факты, инвентарь) = разные файлы для разных хостов. Без него пришлось бы хранить отдельный конфиг для каждого сервера.

Какие фильтры использовались? (минимум 3)
upper — приводит строку к верхнему регистру.

default — подставляет значение, если переменная не задана.

join — объединяет элементы списка в одну строку.

Почему один шаблон дает разные результаты на node1 и node2?
Потому что при gather_facts: yes Ansible снимает факты с каждого хоста отдельно. Переменные, такие как ansible_hostname и ansible_default_ipv4.address, у узлов разные, и Jinja2 подставляет их при рендеринге. Шаблон один — данные разные.

Чем notify отличается от прямого вызова restart?
Прямой restart срабатывает при каждом прогоне плейбука — даже если ничего не менялось, то есть дает лишний простой.notify же только помечает обработчик, а тот запускается один раз в конце и только при условии, что задача действительно внесла изменения (changed).

Что делает listen в обработчике?
listen задает тему (topic), на которую можно отправлять уведомления. Разные задачи могут вызывать notify с одним и тем же именем темы, а обработчик, прослушивающий ее, выполнится один раз. Это упрощает связь между задачами и обработчиками.
