## Вопросы и ответы

### 1. Что такое Jinja2 и почему он используется в Ansible?

**Jinja2** — это современный язык шаблонов для Python. В Ansible он используется для генерации динамических конфигурационных файлов на основе переменных (фактов хоста, inventory и т.д.), что позволяет использовать один шаблон для сотен разных серверов.

### 2. Какие фильтры вы использовали в шаблонах? (минимум 3)

- **`upper`** — переводит строку в верхний регистр
- **`default`** — задаёт значение по умолчанию
- **`join`** — объединяет элементы списка в строку

### 3. Почему шаблон рендерится по-разному на node1 и node2, хотя файл один?

Потому что Ansible собирает "факты" (facts) с каждого хоста (`gather_facts: yes`). Переменные вроде `ansible_hostname` и `ansible_default_ipv4.address` уникальны для каждой ноды, поэтому Jinja2 подставляет разные значения при рендеринге.

### 4. В чём разница между `notify` и прямым вызовом `restart` в tasks?

Прямой `restart` перезапускает сервис при каждом запуске плейбука, вызывая простой. `notify` отправляет сигнал handler'у, который срабатывает только один раз в конце плейбука и только если задача реально внесла изменения (`changed`).

### 5. Что делает `listen` в handler и зачем он нужен?

`listen` создаёт тему (topic) для уведомлений. Несколько разных задач могут вызывать `notify: reload web config`, и handler, "слушающий" эту тему, выполнится один раз, что упрощает управление зависимостями.
