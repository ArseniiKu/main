# Отчёт A1: Jinja2 + Handlers

1. Что такое Jinja2 и зачем он в Ansible?

Jinja2 — шаблонизатор на Python. В Ansible он нужен, чтобы собирать конфиги «на лету»: один шаблон + переменные (факты, inventory) = разные файлы для разных хостов. Без него пришлось бы держать отдельный конфиг под каждый сервер.

2. Какие фильтры использовались? (минимум 3)

upper — приводит строку к верхнему регистру.

default — подставляет значение, если переменная не задана.

join — склеивает элементы списка в одну строку.

3. Почему один шаблон даёт разный результат на node1 и node2?

Потому что при gather_facts: yes Ansible снимает факты с каждого хоста отдельно. Переменные вроде ansible_hostname и ansible_default_ipv4.address у узлов разные, и Jinja2 подставляет их при рендеринге. Шаблон один — данные разные.

4. Чем notify отличается от прямого вызова restart?

Прямой restart срабатывает при каждом прогоне плейбука — даже если ничего не менялось, то есть даёт лишний простой. notify же только помечает обработчик, а тот запускается один раз в конце и лишь при условии, что задача реально внесла изменения (changed).

5. Что делает listen в обработчике?

listen задаёт тему (topic), на которую можно слать уведомления. Разные задачи могут вызывать notify с одним именем темы, а обработчик, слушающий её, выполнится один раз. Это упрощает связи между задачами и обработчиками.
