 Отчёт по заданию A1: Ansible Vault — шифрование секретов


### 1. Что такое Ansible Vault и какой алгоритм шифрования он использует?
**Ansible Vault** — это встроенный механизм шифрования файлов в Ansible, который позволяет безопасно хранить секреты (пароли, API-ключи, сертификаты) в Git-репозитории. Он использует алгоритм **AES-256** (Advanced Encryption Standard с 256-битным ключом) — это стандарт индустрии для симметричного шифрования.

При шифровании файла Vault добавляет заголовок `$ANSIBLE_VAULT;1.1;AES256`, который указывает версию и алгоритм. При запуске плейбука Ansible автоматически расшифровывает файл на лету, если передан правильный пароль.

### 2. Почему важно использовать `no_log: true` в задачах с секретами?
Параметр `no_log: true` предотвращает вывод значений переменных в логи Ansible. Без этого параметра:
- Секреты (пароли, ключи) будут видны в выводе `ansible-playbook` в открытом виде
- При использовании `--verbose` или `-vvv` секреты попадут в логи CI/CD систем
- Злоумышленник с доступом к логам получит все пароли

Пример:
```yaml
- name: Show secret
  debug:
    msg: "{{ db_password }}"
  no_log: true  # Скрывает значение в логах
3. Что произойдёт, если забыть vault-пароль?
Файл будет невозможно расшифровать. Ansible Vault не имеет механизма восстановления пароля — это особенность AES-256. Потеря пароля означает:

    Невозможность запустить плейбуки, использующие этот файл
    Необходимость создать новый vault-файл с новыми секретами
    Обновление всех систем, которые использовали старые секреты

Рекомендация: Хранить vault-пароль в менеджере паролей (Bitwarden, 1Password) или использовать vault-password-file в CI/CD.
4. Почему файл config.ini имеет права 0600?
Права 0600 означают:

    Владелец (root или app_user): чтение + запись
    Группа: нет доступа
    Остальные: нет доступа

Это критично для файлов с секретами, потому что:

    Предотвращает чтение паролей другими пользователями системы
    Соответствует принципу наименьших привилегий (PoLP)
    Требуется стандартами безопасности (PCI-DSS, SOC2)

5. Как бы вы передали vault-пароль в CI/CD без интерактивного ввода?
Способы (от наиболее безопасного к наименее):

    Переменная окружения в GitLab CI:
   script:
     - echo "$VAULT_PASSWORD" > .vault_pass
     - ansible-playbook deploy.yml --vault-password-file .vault_pass
   Где $VAULT_PASSWORD — защищённая переменная в настройках проекта.
Vault-password-file скрипт:
   #!/bin/bash
   echo "$VAULT_PASSWORD"
HashiCorp Vault или AWS Secrets Manager:
export VAULT_PASSWORD=$(vault kv get -field=password secret/ansible)
