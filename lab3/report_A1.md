 Отчёт по заданию A1: Ansible Vault — шифрование секретов


1. Что такое Ansible Vault и какой алгоритм шифрования он использует?

Ansible Vault — встроенное средство Ansible для шифрования файлов, благодаря которому секреты (пароли, API-ключи, сертификаты) можно хранить прямо в Git-репозитории, не опасаясь утечки. Шифрование выполняется по алгоритму AES-256 — симметричному стандарту, широко применяемому в индустрии.

Зашифрованный файл начинается с заголовка $ANSIBLE_VAULT;1.1;AES256, где указаны версия формата и алгоритм. Когда плейбук запускается с правильным паролем, Ansible расшифровывает файл на лету — вручную ничего расшифровывать не нужно.

2. Почему в задачах с секретами важен no_log: true?

no_log: true запрещает Ansible выводить значения переменных в лог. Без него:

секреты (пароли, ключи) будут видны в выводе ansible-playbook в открытом виде;

при -v/-vvv они попадут в логи CI/CD-систем;

любой, у кого есть доступ к логам, получит все пароли.

Пример:

yaml
- name: Show secret
  debug:
    msg: "{{ db_password }}"
  no_log: true  # значение не попадёт в лог
3. Что будет, если забыть vault-пароль?

Расшифровать файл не получится: механизма восстановления пароля у Ansible Vault нет — это свойство AES-256. Последствия:

плейбуки, использующие этот файл, запустить нельзя;

придётся создать новый vault-файл с новыми секретами;

все системы, где использовались старые секреты, нужно обновить.

Рекомендация: хранить пароль в менеджере паролей (Bitwarden, 1Password) или передавать его через vault-password-file в CI/CD.

4. Почему у файла config.ini права 0600?

0600 означает: владелец (root или app_user) — чтение и запись, группа — никаких прав, остальные — никаких прав.

Для файла с секретами это принципиально:

другие пользователи системы не смогут прочитать пароли;

соблюдается принцип наименьших привилегий (PoLP);

выполняется требование стандартов безопасности (PCI-DSS, SOC2).

5. Как передать vault-пароль в CI/CD без интерактивного ввода?

Варианты — от наиболее безопасного к менее безопасному:

Защищённая переменная в GitLab CI:

yaml
script:
  - echo "$VAULT_PASSWORD" > .vault_pass
  - ansible-playbook deploy.yml --vault-password-file .vault_pass
где $VAULT_PASSWORD задаётся в защищённых переменных проекта.

Vault-password-file как скрипт:

bash
#!/bin/bash
echo "$VAULT_PASSWORD"
Внешний менеджер секретов (HashiCorp Vault, AWS Secrets Manager):

bash
export VAULT_PASSWORD=$(vault kv get -field=password secret/ansible)
